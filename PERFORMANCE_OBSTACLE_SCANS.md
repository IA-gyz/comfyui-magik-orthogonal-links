# Obstacle scan efficiency — v0.4.7

A synthetic worker CPU profile of route cleanup highlighted collision scanning and garbage collection. Cleanup previously mapped every rectangle into a temporary record, filtered that list and repeatedly sliced the candidate path. Validation also filtered the complete obstacle array separately for every segment.

These operations now use direct scans. A common segment/rectangle predicate retains the original strict inequalities, including boundary-contact behavior. Endpoint exemptions still compare rectangle object identity. Collision-ID sets preserve obstacle-array order and stop after the first hit for each obstacle. The resulting algorithm remains O(obstacles × path segments), while avoiding the intermediate arrays and closures in the repeated collision scans.

## Measurements

Three independent processes per version/fixture; median total automatic-routing time using actual Node workers. Baseline is the frozen complete v0.4.6 JavaScript directory. Raw samples and hashes are in tests/obstacle_scan_results.json.

| Connections | v0.4.6 | v0.4.7 | Reduction |
|---|---:|---:|---:|
| 80 | 158.90 ms | 137.79 ms | 13.3% |
| 160 | 265.34 ms | 238.05 ms | 10.3% |
| 500 | 964.73 ms | 769.25 ms | 20.3% |

Every before/after render and committed-route hash matches across all samples. A 500-connection cancellation test stopped in 77.2 ms and committed zero routes. These are synthetic CPU/worker measurements, not live ComfyUI browser/GPU results. The initial worker profile used 150 cleanup requests, 1,000 rectangles and 500 reference routes; this is a focused fixture, not a representative user workflow.

## Verification and limits

- 4,000 direct-scan comparisons against the original filter/predicate behavior, including duplicate rectangle objects and endpoint exemptions.
- Strict boundary contacts, zero-length segments, and equal-valued but nonidentical exemption rectangles.
- 100 deterministic cleanup/nudging snapshots generated by v0.4.6, checked by a combined SHA-256 digest.
- 1,500 exhaustive validation-report comparisons, with a frozen independent obstacle predicate and spacing implementation.
- Existing simulated UI, actual workers, transport resets, index oracles, shared endpoints, independent maze checks and real libavoid WASM scene tests pass.

No candidate budgets, pathing heuristics, pass ordering, cache lifetime or commit behavior changed. Dense scenes still require obstacle scans; this release reduces allocation and traversal overhead rather than changing their asymptotic complexity.
